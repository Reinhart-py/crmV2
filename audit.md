# CRM Complete Repository Audit (audit.md)

## 1. Critical Priority: Security Breaches, Auth Flaws & Fatal Crashes

- [ ] **[Security / `application/controllers/ci_admin.php:86-100`]** Hardcoded password bypass allows any user entering common passwords ('admin', 'password', '123456') to authenticate as Super Admin without verifying email or username -> Remove hardcoded password array fallback condition and enforce strict database credential verification.
- [ ] **[Security / `application/views/manager/reset.php:59-64`]** Password reset form inputs use `type="text"`, exposing newly set passwords in cleartext on screen and browser DOM history -> Change input types to `type="password"`.
- [ ] **[Security / `application/views/manager/user/adduser.php:50`]** User registration password input uses `type="text"`, exposing passwords visibly during account creation -> Change input type to `type="password"`.
- [ ] **[Security / `application/config/config.php:309`]** CSRF protection is globally disabled (`$config['csrf_protection'] = FALSE;`), leaving all CRM state-changing forms and AJAX POST endpoints vulnerable to cross-site request forgery -> Enable CSRF protection with token regeneration and include CSRF tokens in forms and AJAX headers.
- [ ] **[Security / `application/views/manager/loginpage.php:92-96`]** Public unauthenticated login screen exposes direct link to external Cloudflare Worker data generation API (`7strokes.maxvendor47.workers.dev`) -> Remove public data generator link from login page and restrict behind authenticated admin routes.
- [ ] **[Security / `application/controllers/ci_admin.php:202-210`]** Password reset OTP uses weak `rand(00000000, 99999999)` with octal literal parsing and has no expiration timestamp in database, allowing permanent replay -> Use `random_int()` or cryptographically secure token with a 15-minute expiration timestamp column in `ci_user`.
- [ ] **[Security / `application/controllers/ci_admin_calls.php:206-207`]** Direct string interpolation of `$_GET['search']` in live search queries creates SQL injection vulnerability -> Sanitize input with `$this->db->escape_like_str($search)` or use CodeIgniter query builder methods.
- [ ] **[Security / `application/models/ci_admin_model.php:1676`]** Raw query concatenation in live search filter introduces SQL injection exposure -> Parameterize query bindings or use `$this->db->like()`.
- [ ] **[Fatal / `application/controllers/ci_admin_team.php:180,184,193,197,201,253,257,266,270,274,323,327,336,340,344,391,395,404,408,412`]** Unchecked `implode(',', $var)` on GET filter parameters (`country`, `state`, `status`, `category`, `lCat`) throws fatal `TypeError` in PHP 7.4/8+ when scalar values are passed -> Wrap all filter inputs with `if (is_array($var)) { $var = implode(',', $var); }`.
- [ ] **[Fatal / `application/controllers/ci_admin_leads.php:166,170,180,184,188,235,239,248,252,256,1738,1742,1750,1753,1756`]** Unchecked `implode(',', $var)` on filter parameters throws fatal `TypeError` on string GET values -> Guard every `implode` with `is_array()` checks before concatenating.
- [ ] **[Fatal / `application/controllers/ci_admin_verticals.php:68,72,116,119`]** Unchecked `implode(',', $var)` on GET filter parameters throws fatal `TypeError` on string inputs -> Add `is_array()` checks prior to calling `implode()`.
- [ ] **[Fatal / `application/controllers/ci_admin_team.php:227`]** Missing default parameter in `public function followups($action, $type=0)` throws fatal `ArgumentCountError` when accessed via routed URL `/manager/team/followups` -> Change function signature to `public function followups($action = '', $type = 0)`.
- [ ] **[Fatal / `application/controllers/ci_admin_setting.php:8,96`]** Controller attempts to load non-existent model `ci_site_model` on logo update, crashing with CodeIgniter model loader fatal error -> Replace `ci_site_model` with `comman_model` for saving site settings.
- [ ] **[Fatal Recursion / `application/models/report_model.php:34-58`]** `fetchTeamListByDepartment()` passes `$row['id']` (user ID) recursively into the `$department` parameter, querying department by user ID and causing fatal infinite recursion / memory exhaustion on empty department -> Refactor query to fetch flat user IDs matching department without recursive self-calling.
- [ ] **[PHP 8 Compatibility / `application/controllers/ci_admin.php:305,307,346,376`]** Direct array dereference `$this->session->userdata['key']` triggers PHP 8 undefined index warnings and notices -> Replace with standard CodeIgniter method call `$this->session->userdata('key')`.
- [ ] **[PHP 8 Compatibility / `application/views/manager/elements/header.php:356`]** Direct array dereference `$this->session->userdata['manager_role']` triggers PHP notices on unauthenticated or session-expired states -> Change to `$this->session->userdata('manager_role')`.
- [ ] **[PHP 8 Warning / `application/views/manager/leads/single_view.php:566-579`]** Hardcoded `for($i=0;$i<=6;$i++)` on `$bo_list` throws undefined offset notices when a lead has fewer than 7 back-office records -> Replace with `foreach($bo_list as $bo)`.

## 2. High Priority: Data Corruption, Infinite Loops, Broken Workflows & 404 Routes

- [ ] **[Data Corruption / `application/controllers/ci_admin_leads.php:672`]** Lead edit saves raw `$r_date` without converting format via `db_date($r_date)`, inserting `0000-00-00` into MySQL DATE column -> Convert with `db_date($r_date)` before updating database.
- [ ] **[Data Corruption / `application/controllers/ci_admin_tasks.php:160,168,169,177`]** Task creation saves raw dates (`r_date`, `tl_issue_date`, `tl_expire_date`, `dnd_check_date`) directly from POST without `db_date()`, corrupting dates in MySQL -> Wrap all four date fields in `db_date()` before database insertion.
- [ ] **[Data Corruption / `application/controllers/ci_admin_tasks.php:297,305,306,314`]** Task edit saves raw date fields without `db_date()`, resetting valid dates to `0000-00-00` on edit -> Apply `db_date()` to `r_date`, `tl_issue_date`, `tl_expire_date`, and `dnd_check_date` in task edit handler.
- [ ] **[Data Integrity / `application/controllers/ci_admin_leads.php:1001-1009`]** Lead delete AJAX method deletes from `ci_leads`, `ci_boleads`, and `ci_followup`, but leaves orphaned records in `ci_meetings` and `ci_call_logs` -> Add cascade deletion queries for `ci_meetings` and `ci_call_logs` matching the target lead ID.
- [ ] **[Broken Workflow / `application/controllers/ci_admin_report.php:85,130`]** Hardcoded `die;` statements at the beginning of `leads()` and `followup()` methods terminate execution with completely blank pages -> Remove `die;` and let report views render properly.
- [ ] **[Data Bug / `application/models/ci_admin_model.php:1661`]** Date range query in `getMyVerticals()` uses undefined variables `$date1` and `$date2` instead of function parameters `$d1` and `$d2`, triggering PHP notices and returning zero records -> Correct variable names to `$d1` and `$d2`.
- [ ] **[Data Bug / `application/models/report_model.php:148`]** Performance report queries hardcode status IDs `status = 42` and `status = 39` directly in SQL, breaking whenever status table IDs change -> Dynamically resolve status IDs from `ci_status` by slug or name.
- [ ] **[Routing 404 / `application/controllers/ci_admin_meetings.php:95`]** Redirect points to misspelled route `manager/meetingss` after meeting creation, triggering 404 error -> Fix redirect path to valid route.
- [ ] **[Routing 404 / `application/controllers/ci_admin_meetings.php:121,151`]** Redirects point to `manager/meetings`, but no route exists for meetings in `application/config/routes.php` -> Add `$route['manager/meetings'] = 'ci_admin_meetings/index';` and associated CRUD routes to `routes.php`.
- [ ] **[Routing 404 / `application/controllers/ci_admin_leads.php:940,950`]** Redirects point to non-existent controller method `ci_admin_leads/leads_info` -> Update redirect to valid lead detail route `manager/leads/view/$1`.
- [ ] **[Routing 404 / `application/controllers/ci_admin_terms.php:172`]** Redirect points to non-existent route `manager/category-tree` -> Register route in `routes.php` or redirect to `manager/categories`.
- [ ] **[Routing 404 / `application/config/routes.php:98`]** Route `manager/category-delete/(:any)` points to non-existent controller `ci_admin_category/delete/$1` -> Point route to `ci_admin_terms/delete/$1`.
- [ ] **[Routing 404 / `application/config/routes.php:89-92`]** Missing route rule for role deletion `manager/roles/delete/(:num)` causing role delete links to return 404 -> Add `$route['manager/roles/delete/(:num)'] = 'ci_admin_roles/delete/$1';`.
- [ ] **[Routing 404 / `application/views/manager/setting/user.php:102`]** User delete link points to `manager/user/delete/(:any)` which does not exist in `routes.php` -> Add route or point link to `manager/users/delete/$1`.
- [ ] **[Broken Route / `application/config/routes.php:68-69`]** Route `manager/team/verticals` maps to `ci_admin_verticals/teams/$1` passing unmatched `$1` string literal to zero-argument `teams()` method -> Change route destination to `ci_admin_verticals/teams`.
- [ ] **[Broken UI Action / `application/views/manager/leads/leadsview.php:502`]** Relative AJAX path `url: 'deleteleads/' + id` breaks when invoked from nested URLs such as `manager/leads/followups` -> Prepend base URL: `url: '<?php echo base_url(); ?>manager/deleteleads/' + id`.
- [ ] **[Schema Out of Sync / `database/localhost.sql`]** Base database dump is missing new schema tables `ci_tasks`, `ci_call_logs`, `ci_admin_logs`, and updated `ci_tickets` columns, causing fresh installations to fail -> Update `localhost.sql` or add an automatic migration runner step to installation instructions in `README.md`.
