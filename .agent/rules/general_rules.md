# General Rules

## Code quality
- Write clean, human-readable, maintainable code.
- Use natural naming conventions and straightforward logic.
- Reuse existing components, helpers, models, controllers and styles wherever possible.
- Do not introduce unnecessary dependencies.
- Directly modify files without generating temporary scratch scripts.

## Code appearance
- Never use emojis in code, documentation or development output.
- Do not write inline comments inside source code files.
- No pill icons, rainbow colours, or unnecessary decorative UI.
- Use proper SVG icons from standard icon sets.
- Order Details and View pages must strictly match Preview Lead (single_view.php) layout, styling, and UX.

## Development behaviour
- Understand existing functionality before modifying it.
- Modify source files directly.
- Do not remove working features while implementing new ones.
- Do not change unrelated pages, navigation, layouts or components.
- Do not introduce new UI elements unless specifically requested.
- Never use fake data, hardcoded demo values or placeholder records.
- Implement permissions in the backend, not just by hiding frontend elements.
- Do not make assumptions about database columns or existing functionality. Inspect actual implementation first.
- take real actions and make changes instead of wasting time in just thinking . 
- 


## Communication
- No unnecessary introductions or lengthy explanations.
- Focus on completing the requested work.
